# LB_CALC_WEB

## Описание

Тренировочное web-приложение для расчёта размеров и визуализации автоматических камер хранения и постаматов.

Приложение позволяет:

* создавать и редактировать проекты;
* хранить данные в MySQL;
* рассчитывать размеры конструкций;
* формировать коммерческие предложения с техническими характеристиками и эскизами;
* регистрировать и авторизовывать сотрудников с разграничением доступа по ролям;
* отправлять пользовательские события и email-уведомления.

## Цели

Практическое освоение:

* Java и Spring Boot;

* Spring Security и JWT;

* Apache Kafka;
* Docker и Docker Compose;

* Apache POI и Java IO;
* Git;
* ООП, SOLID и MVC.

## Архитектура

Проект состоит из:

* `lb-calc-web` — основное web-приложение;
* `notification-service` — сервис обработки событий и отправки email;
* `MySQL` — база данных;
* `Kafka` — обмен событиями между сервисами.

```text
LB Calc Web → Kafka → Notification Service → Email
      ↓
    MySQL
```

## Запуск

Сборка проекта:

```bash
./mvnw clean package
```

Запуск Docker-окружения разработки:

```bash
cd environments/dev
docker compose --env-file dev.env up -d --build
```

Тестовое окружение использует отдельную БД `lb_calc_web_test`, отдельный Docker volume и отдельные порты. Оно не должно подключаться к БД разработки.

Подготовка и запуск тестового окружения:

```bash
cp environments/test/test.env.example environments/test/test.env
cd environments/test
docker compose --env-file test.env up -d --build
```

При необходимости запуск тестов из IntelliJ IDEA выполняется с профилем `test`. По умолчанию он подключается к `localhost:3308/lb_calc_web_test`; параметры подключения можно переопределить переменными `DB_URL`, `DB_USERNAME` и `DB_PASSWORD`.

Flyway автоматически применяет миграции при запуске приложения. V1 создаёт актуальную схему БД с нуля, Hibernate проверяет её соответствие Entity через `ddl-auto=validate`. Не создавать и не изменять таблицы вручную.

Переход со старой схемы на пересобранную V1 требует однократного пересоздания БД, поскольку прежние записи Flyway ссылаются на удалённые V2/V3. Для Docker-окружения DEV, если в нём нет нужных данных:

```bash
cd environments/dev
docker compose --env-file dev.env down -v
docker compose --env-file dev.env up -d --build
```

Для полного сброса только тестового окружения:

```bash
cd environments/test
docker compose --env-file test.env down -v
docker compose --env-file test.env up -d --build
```

Команда `down -v` удаляет данные соответствующих Docker volumes. Не выполнять её для окружений, данные которых требуется сохранить. Для внешней MySQL БД необходимо отдельно удалить и создать заново именно целевую БД перед первым запуском новой версии.

Основное приложение DEV:

`http://localhost:8081`

Notification Service DEV:

`http://localhost:8082`

Kafka DEV при запуске приложения из IntelliJ IDEA:

`localhost:29092`
